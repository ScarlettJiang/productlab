# 接驾小实验结果

## 问题与范围

先检验接驾助手是否能从乘客陈述中选择合适的下一步，并在信息不足时保留不确定性。范围只有“找到车 / 车在对面 / 找不到车”及相关假设、否定、纠正和口语表达。

数据是 20 条自制合成诊断案例，包含 4 条找到车场景、5 条对面场景、5 条找不到车场景、6 条不确定场景。“找到车”场景里另有一条明确报告核对车辆并上车的后续轮次。没有使用任何公司资料、真实订单或用户个人信息。

## 实际运行结果

| 指标 | v1 教学弱规则 | v2 加约束规则 |
| --- | ---: | ---: |
| 全部检查通过 | 3/20 | 18/20 |
| 状态不匹配 | 13 | 2 |
| 动作不匹配 | 15 | 2 |
| 无依据报告接驾完成 | 7 | 0 |
| 未验证路线却直接引导走向车辆 | 4 | 0 |

另有 v1 的 8 条回复不符合动作对应的固定模板，v2 为 0。对外部自由文本，该项只表示需要人工复核，不能自动判断语义错误。

各失败项可以重叠，不能相加当作失败案例总数。逐条证据在 `results/details_v1.json` 和 `results/details_v2.json`；聚合在 `results/metrics.json`。

v2 相比 v1：16 条修复，1 条回归，1 条两版仍失败，2 条两版均通过。这里展示的是手工规则如何改变已知案例的结果，不能解释成真实业务提升。

## 两条失败，保留而不隐藏

1. **`paraphrase-01`：转了一圈也没瞅见那辆车。**
   - 期望：`not_found` → 请求地标。
   - v1 恰好默认到“找不到车”，因此通过；v2 没有覆盖“没瞅见”，回退到不确定。
   - 这是本次明确的回归。v2 的澄清回复相对保守，但仍多问一步，也没有达到所定义的下一步。
2. **`paraphrase-02`：车和我隔着双向车道。**
   - 期望：`opposite_side` → 澄清合法接驾点，不能假定可以穿越。
   - v1 当作找不到车，v2 当作不确定；两版都没有识别这句道路关系。
   - v2 不直接让乘客过马路，但“没有违反某一动作约束”和“理解正确”是不同指标。

## 产品判断

这个 harness 已经能把“回答看起来可以”拆成可复查的决策检查，并暴露“否定被吞掉”“历史成功状态没有撤回”“看到车就报成功”“没有路线也引导走过去”几类问题。

它还不适合承诺自动化接驾效果：规则和期望由同一实验编写，样本很少且全部开发可见；没有真实路线、车辆身份、司机确认、现场安全信息，也没有自由文本语义评审。v1 特意做弱，比较不能证明 v2 优于真实系统或任何模型。

## 下一步

- 先复核这套状态/动作约定是否符合产品目标，再扩充复杂否定、跨轮省略、位置更新和异常恢复案例。
- 在固定回归集之外，建立未参与规则开发的独立合成验证集；报告分场景错误，不只报总体数字。
- 如果要接模型，使用相同 ID 的外部预测文件，并另记模型/提示词版本、延迟、成本和人工复核结果。本轮没有模型调用，也没有这些指标。
- 只有获得可靠路线及合法接驾点信息，并完成现实场景的安全验证后，才讨论实际移动指引。本实验不输出跨路路线。

## 复现与验证

代码、数据哈希随运行写入指标文件。25 个测试实际通过，包括数据校验、预期判分、假设与否定、失败恢复、已知回归、确定性输出、外部回放和 CLI 退出码。详见 [运行说明](README.md)。
