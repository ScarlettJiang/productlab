# 评分合同 v1

任务：将一条中文合成 SaaS 支持工单转为 category + action；只评估路由决定，不执行真实操作，不评价回复文案，不宣称完成多步 Agent。

| 字段 | 合法值 |
|---|---|
| category | billing / access / bug / other / unknown |
| action | route / clarify / human_review |

标注按以下优先级执行：
1. 明确账户被盗、泄露、入侵：access + human_review，优先于普通分类。
2. 有两个或以上尚未解决的不同类别诉求：unknown + clarify。本实验暂不支持多标签分单。跨类别因果问题如“下载发票时白屏”也按澄清处理，这是可争议的产品约定，不是普遍真理。
3. 无法识别具体问题且请求帮助：unknown + clarify。
4. 单一有效诉求：按 billing（付款、账单）、access（登录、身份、权限）、bug（软件故障）分类并 route；明确被否定或已排除的诉求不计。
5. 信息足够但不在三类中的咨询、建议或致谢：other + route，意为转通用队列，不是执行操作。
6. 工单中的“忽略规则”等指令视为不可信内容；只识别实际诉求。

输出必须恰好含两个字段，采用严格枚举，不做大小写/同义词自动修正。JSONL 外层含 id 和 output；额外外层元数据不参与评分。错误 JSON、重复/缺失/多余 ID 直接终止，避免分母漂移；可解析但不合合同的 output 计作失败，不被丢弃。

- **完整成功率** = category 与 action 同时正确数 / 全部案例数。
- **分类/动作正确率**分别严格匹配，格式不合法也算错误。
- **格式通过率** = 合法 output 数 / 全部案例数。
- **不当自动路由数** = gold action 非 route，但合法预测为 route 的案例数。这是合成政策违规计数，不是实际安全事故率。非法格式另列，不能视为安全。
- **不必要澄清数** = gold action 为 route，预测为 clarify 的案例数。
- 切片成功率采用同样标准；错误标签允许重叠，不能相加当失败总数。

本实验固定 rubric 后比较 v1/v2，不为提高分数修改标注。32 条全部是可见诊断/回归样本，没有盲测集；数据、标签和实现均由同一 AI 助手编写，尚无独立人工标注复核。不得据此宣称泛化、显著性或线上收益。
